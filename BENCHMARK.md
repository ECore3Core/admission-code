# Измерение задержки

```console
python benchmark_admissions.py input.json --out results/run --repeats 5
```

Формат показан в `example.json`. Для частных исторических данных создайте
вне публикуемой папки собственный JSON с теми же полями. `metadata.kind`
принимает `real` или `synthetic`; описание обязательно. Для реконструкции
реальных снимков используется `real`, а в `metadata.description` явно
указываются способ восстановления и ограничения.

`pools` содержит id, program, capacity, category; `totals` — бюджеты программ.
`initial_students` — агрегаты до первого события. `events` — упорядоченные
события с уникальным id, timestamp, op. Для add/replace передаётся полный
student: id, offers, original, consent, locked_pool. В offers указываются
pool, priority, route_order, key (целые числа), basis. Для remove вместо
student передаётся student_id. Идентификаторы должны быть условными.

Сравниваются три пути после каждого события: local, full, wave. Во всех
применяются одинаковые правила, планы мест, кучи и упорядоченные индексы.
Полные варианты строят новое состояние; локальный сохраняет предыдущее.
Волновой вариант откладывает новое предложение отклонённого участника до
следующего раунда. `waves_both_scenarios` — сумма волн по двум сценариям.

Один полный прогрев исключается, затем выполняются заданные повторы.
Каждый повтор начинает с одного снимка. Порядок трёх замеров перемешивается
с воспроизводимым seed. Таймер perf_counter_ns включает ядро и индексы;
подготовка агрегатов, сравнение результатов, БД и запись файлов исключаются.
Локальный метод дополнительно формирует дельту назначений; полные возвращают
готовое состояние без дельты. Это дополнительная работа локального пути,
её нужно учитывать при интерпретации ускорения. Сквозная задержка сервиса
здесь не измеряется.

После каждого события назначения и страницы рейтингов всех трёх вариантов
сравниваются вне таймера. При расхождении работа завершается ошибкой.
Сводка содержит p50/p95/p99 по правилу ближайшего ранга, максимум,
суммарную длительность и число уникальных событий. Для малых групп есть
предупреждение о размере выборки p99. Повторы не заменяют разные события.

Текущий инструмент измеряет отдельные add/replace/remove. При восстановлении
дневных снимков необходимо отдельно решить, измеряется весь дневной пакет
или детерминированная последовательность агрегатов. Нельзя делить время
пакета на число строк и называть результат задержкой отдельного события.
Смена этапа и плана мест выносится в отдельный опыт.

Excel-аудит считает объёмы, но не конвертирует выгрузку в готовый журнал
распределения. Без плана мест, полного разрешения равенств и нормализации
оснований автоматическая конвертация создала бы неподтверждённую модель.
