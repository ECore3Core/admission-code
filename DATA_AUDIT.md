# Локальный аудит Excel

Для чтения Excel нужен только дополнительный пакет openpyxl:

```console
python -m pip install -r requirements-audit.txt
python audit_excel.py PATH_TO_PRIVATE_DIRECTORY --out local-results/audit.json
```

Скрипт не использует сеть. Читает локальные `.xlsx`, лист «Абитуриенты».
У экспорта некорректно записана область листа A1:A1, поэтому перед чтением
вызывается reset_dimensions. Заголовок определяется по названиям полей.
Учитываются строки с числовым значением в столбце «№».

Определения результатов:

- rows: число исходных строк, включая незавершённые записи.
- N: число различных значений «Личный номер». Это учётные записи кампании.
  Проверки по СНИЛС выводят только числа, сами значения не сохраняются.
- E_observed: число различных пар (личный номер, ключ группы), без
  многократного счёта одного маршрута. Конфликтующие приоритеты считаются отдельно.
- G_observed: число групп, представленных хотя бы одной записью. Ключ:
  филиал, набор ОП, финансирование, форма обучения, вид приёма, дополнительный
  набор, целевой приём, отдельная квота, особая квота, предложение ЦП.
- valid_routes: те же показатели после исключения строк без набора ОП,
  приоритета или финансирования. Это структурная проверка, не полный допуск.
- budget: структурно полные маршруты с финансированием «бюджет».
- D_filing: число различных непустых распознанных дат подачи.

Число файлов-снимков и D_filing различаются. Дата в имени файла также может
отличаться от дат записей и времени создания книги. Скрипт сохраняет это
различие. Объединение личных номеров нескольких снимков применяется только
внутри одной кампании; для нескольких лет запускайте аудит раздельно.

G_observed нельзя отождествлять с числом независимых пулов математической
модели. В выгрузке может не быть пустых конкурсов; БВИ и общий конкурс могут
использовать общий ресурс, а целевой набор требует детализации. Итоговый G
получается после сопоставления с планом приёма.

Результат содержит агрегаты и имена исходных книг, но не ФИО, контакты,
личные номера или строки заявлений. Исходники и сам результат аудита
не включаются в поставку проекта. Доступность только итоговых значений
полей не позволяет восстановить все промежуточные изменения.
