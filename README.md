# Инкрементальное обновление конкурсных списков

Исследовательский проект для одного университета. Версия приложения v4,
согласованная с доработкой обзора от 28.10.2026.

Проект содержит исходный код, тесты и инструменты воспроизведения измерений.
Исходных Excel-файлов, записей абитуриентов, идентификаторов, результатов
обработки частных выгрузок и ключей доступа в проекте нет.
Публиковать можно код этой папки; реальные данные остаются у владельца.

## Быстрый запуск

Python 3.10 или новее. Для алгоритма, примера и тестов сторонние пакеты не нужны.

```console
python university_admissions.py
python -m unittest discover -v
python benchmark_admissions.py example.json --out results/demo --repeats 5
```

`example.json` — небольшой вручную составленный пример формата, не данные
приёмной кампании. Его задержки не являются результатами статьи.

## Состав

| Файл | Назначение |
| --- | --- |
| university_admissions.py | Агрегаты Student/Offer/Pool, каскадное добавление, компонентный пересчёт, два сценария |
| ranking_index.py | Упорядоченный индекс заявлений с выдачей страниц и позиций |
| benchmark_admissions.py | Полный очередной, полный волновой и локальный варианты; воспроизведение событий и замеры |
| test_university_admissions.py | Независимый эталон на списках, смешанные события, квоты, БВИ, приказы и подтверждения |
| test_baselines.py | Сопоставление трёх вариантов, волновая цепочка и проверка протокола замеров |
| audit_excel.py | Только локальный подсчёт объёмов выгрузок, без вывода строк абитуриентов |
| BENCHMARK.md | Формат событий и точная граница измерения |
| DATA_AUDIT.md | Определения показателей и ограничения подсчёта по Excel |

## Интерфейс расчётного ядра

```python
from university_admissions import Pool, Offer, Student, UniversityEngine

engine = UniversityEngine(
    [Pool('A:main', 'A', 1, 'main')], {'A': 1}, confirmation='original'
)
student = Student(
    id='demo-a',
    offers=(Offer('A:main', 1, 0, (1, -280, -90, 1), 'exams'),),
    original=True,
)
delta = engine.add(student)
print(engine.assignment('demo-a', 'all'))
print(engine.ranked_page('A:main', 'confirmed', 0, 20))
# engine.replace(full_new_student) — заменить весь агрегат;
# engine.remove('demo-a') — удалить участника.
```

Студент — агрегат всех допустимых маршрутов одного человека. Следующее
заявление уже известного участника требует `replace`, а не `add`.
Меньший конкурсный ключ означает более высокое место. Полные ключи должны
быть строгими: равенства разрешает адаптер правил, ядро не придумывает
победителя. `priority` и `route_order` задают строгий порядок маршрутов.

`all` учитывает всех допустимых участников. `confirmed` использует `consent`
или `original` согласно настройке. `locked_pool` означает закрепление
приказом, а не факт подачи оригинала или согласия.

## Модель и ограничения

Пулы — независимые непересекающиеся части бюджета с фиксированной вместимостью
внутри одного этапа. Адаптер университета проверяет допуск, квоты, особые права,
БВИ и формирует конкурсные ключи заранее. БВИ не создаёт дополнительных мест.
Смена этапа, правил или плана мест требует нового расчётного состояния.
Пулы нельзя автоматически получить из одного списка подавших заявления:
нужен план приёма и правила нормализации конкурсов.

При добавлении нового подвижного участника продолжается очередь предложений.
Ранее отклонённые маршруты не пересматриваются при неизменных ресурсах,
предпочтениях, ключах и допусках старых участников. При изменении или удалении
пересчитывается связная компонента старых и новых маршрутов. Остальные
назначения сохраняются. В худшем случае компонента охватывает весь вуз.

Полный волновой вариант подаёт одно предложение от свободного участника за
раунд и переносит отклонённых в следующий раунд. Это вычислительные волны,
а не календарные этапы приёма.

Индекс использует рандомизированное дерево: оценки времени ожидаемые.
Это исследовательское ядро, а не сервис с транзакциями, авторизацией и
публикацией списков. Вызовы изменения состояния нужно сериализовать.

## Проверка и воспроизводимость

Семь тестов включают 10 000 состояний после смешанных событий и 120 отдельных
наборов для сопоставления очередного и волнового вариантов. Случайные данные
используются только в проверках корректности. Для исследования задержки
используются исторические списки, а не генератор нагрузки.

Результаты замеров создаются локально и исключены из Git. Скрипт сохраняет
хеш входного JSON, хеши исходников, версию Python, ОС и используемый таймер.
Для точного воспроизведения реального эксперимента нужны разрешённый доступ
к данным, план мест и версия адаптера правил. Публикация одного кода не
делает частные данные общедоступными.
